# 高中評量成績「文字評量」輸入/儲存/讀取調整（0105）

## 問題描述

### 現象
使用者無法在高中評量成績畫面中成功儲存「文字評量」欄位的內容。即使輸入文字評量並點擊儲存，重新載入或重新開啟畫面後，文字評量內容會消失。

### 重現步驟
1. 開啟高中評量成績輸入畫面
2. 選擇任一評量（例如：第一次段考）
3. 輸入學生分數（例如：80）
4. 輸入文字評量（例如：`表現良好，持續加油`）
5. 點擊儲存
6. 重新載入頁面或重新開啟畫面
7. **問題**：文字評量欄位為空，先前輸入的內容消失

---

## 根因分析

### 問題點 1：文字評量欄位判斷使用 truthy，無法支援空字串清空
**位置**：`gradebook.js` 第 1683 行（修正前）

```javascript
var hasText = studentRec['Exam' + examRec.ExamID + '_文字評量'];
if (hasText) {
    needExtensionShell = true;
}
```

**問題**：
- 使用 truthy 判斷，當文字評量為空字串 `''` 時，`hasText` 為 `false`
- 導致無法建立 Extension 殼，無法送出清空更新

### 問題點 2：文字評量值未寫入 Extension.Extension.Text
**位置**：`gradebook.js` `SetCourseExamScoreWithExtension` 函式

**問題**：
- 雖然會判斷是否需要建立 Extension 殼（`needExtensionShell`），但**從未將文字評量值寫入 `data.Extension.Extension.Text`**
- 導致後端收不到文字評量資料

### 問題點 3：一般分數路徑會清空 Text，覆蓋文字評量
**位置**：`gradebook.js` 第 1713-1718 行（修正前）

```javascript
// B-3: 一般分數時，保留 Extension 結構但清空三欄位
if (isNormalScore && data.Extension) {
    data.Extension.Extension.Score = '';
    data.Extension.Extension.UseText = '';
    data.Extension.Extension.Text = '';  // ← 此處會清空 Text
}
```

**問題**：
- 當輸入一般分數（非缺考/特殊成績）時，會執行此邏輯清空 `Text`
- 即使使用者有輸入文字評量，也會被此邏輯清空

### 對照：舊版實作（gradebook_old.js）
根據 TODO 文件說明，舊版會：
1. 一律將 `_文字評量` 欄位寫回 `Extension.Extension.Text`
2. 處理單引號 escape：`text.replace(/'/g, "''")`
3. 因此可正常保存與讀取

## 修正方式

### 修正 1：改用 hasOwnProperty 判斷文字評量欄位存在
**位置**：`gradebook.js` 第 1682-1687 行

```javascript
// 檢查是否有文字評量欄位（使用 hasOwnProperty 以支援空字串清空）
var textEvalFieldName = 'Exam' + examRec.ExamID + '_文字評量';
var hasTextField = studentRec.hasOwnProperty(textEvalFieldName);
if (hasTextField) {
    needExtensionShell = true;
}
```

**說明**：
- 改用 `hasOwnProperty` 判斷欄位是否存在，而非 truthy
- 即使文字評量為空字串，只要欄位存在就會建立 Extension 殼
- 支援「清空文字評量」的需求

### 修正 2：調整一般分數清空邏輯，保留文字評量
**位置**：`gradebook.js` 第 1713-1723 行

```javascript
// B-3: 一般分數時，保留 Extension 結構但清空三欄位
// 注意：若存在文字評量欄位，Text 不應在此清空（將在 B-5 寫入）
if (isNormalScore && data.Extension) {
    // 只清空這次功能使用的三個欄位，其餘欄位保留
    data.Extension.Extension.Score = '';
    data.Extension.Extension.UseText = '';
    // 若沒有文字評量欄位，才清空 Text；否則保留給 B-5 寫入
    if (!hasTextField) {
        data.Extension.Extension.Text = '';
    }
}
```

**說明**：
- 當存在文字評量欄位時，不在 B-3 清空 `Text`
- 保留 `Text` 給後續的 B-5 邏輯寫入文字評量值

### 修正 3：新增 B-5 區塊，寫入文字評量值
**位置**：`gradebook.js` 第 1770-1790 行

```javascript
// B-5: 寫入文字評量（必須在所有 Extension 邏輯之後，避免被覆蓋）
if (hasTextField && data.Extension) {
    // 取得文字評量輸入值
    var textEval = studentRec[textEvalFieldName];
    
    // 正規化：若為 null/undefined 視為空字串（支援清空）
    if (textEval === null || textEval === undefined) {
        textEval = '';
    } else {
        // 轉為字串
        textEval = '' + textEval;
    }
    
    // 單引號 escape（參考舊版，避免後端 SQL/字串解析問題）
    textEval = textEval.replace(/'/g, "''");
    
    // 寫入 Extension.Extension.Text
    // 注意：若同時有缺考 extension，此處會覆蓋缺考的 Text
    // 但根據舊版實務運作，文字評量與缺考 Text 共用同一欄位是系統設計
    data.Extension.Extension.Text = textEval;
}
```

**說明**：
1. **執行時機**：在所有 Extension 邏輯之後（B-2、B-3、B-4 之後），確保不會被覆蓋
2. **取值與正規化**：從 `studentRec` 取得文字評量值，處理 `null/undefined` 為空字串
3. **單引號 escape**：參考舊版實作，將單引號 escape 為兩個單引號，避免後端 SQL/字串解析問題
4. **寫入位置**：寫入 `data.Extension.Extension.Text`，與缺考/特殊成績共用同一欄位（符合系統設計）

### 修正邏輯流程圖

```
1. 判斷是否需要 Extension 殼
   ├─ 特殊成績 (be.extension) → needExtensionShell = true
   ├─ 文字評量欄位存在 (hasTextField) → needExtensionShell = true
   ├─ 讀卡子成績 (isSubScoreMode) → needExtensionShell = true
   └─ 一般分數 (isNormalScore) → needExtensionShell = true

2. 建立 Extension 殼（若 needExtensionShell == true）

3. B-2: 寫入特殊成績 Extension（若 be.extension 存在）
   └─ Score, UseText, Text 來自 examExtensionMap

4. B-3: 一般分數清空邏輯（若 isNormalScore）
   ├─ 清空 Score, UseText
   └─ 若無文字評量欄位 → 清空 Text
      └─ 若有文字評量欄位 → 保留 Text（給 B-5 寫入）

5. B-4: 讀卡子成績（若 isSubScoreMode）
   └─ 寫入 CScore, PScore

6. B-5: 寫入文字評量（若 hasTextField）★ 新增
   └─ 寫入 Extension.Extension.Text（含 escape 處理）
```

## 相容性處理

### 缺考/特殊成績 Extension 邏輯
- **保持不變**：`buildScoreAndExtension()` 函式與 `be.extension` 邏輯維持原樣
- **執行順序**：先寫入缺考 extension（B-2），最後寫入文字評量（B-5）
- **欄位共用**：文字評量與缺考 `Text` 共用 `Extension.Extension.Text` 欄位
  - 若同時存在，文字評量會覆蓋缺考 `Text`（符合舊版實務運作）
  - 若僅有缺考，缺考 `Text` 正常寫入（B-2）
  - 若僅有文字評量，文字評量正常寫入（B-5）

### 讀取回填邏輯
- **無需修改**：`gradebook.js` 第 1042 行已正確讀取
  ```javascript
  studentMapping[examScoreRec.StudentID]['Exam' + examScoreRec.ExamID + '_文字評量'] = 
      examScoreRec.Extension.Extension.Text == undefined ? '' : examScoreRec.Extension.Extension.Text;
  ```

## 可能風險與回歸點

### 風險 1：文字評量與缺考 Text 共用欄位
**說明**：
- `Extension.Extension.Text` 同時承載「缺考文字」與「文字評量」
- 若使用者同時輸入缺考代碼與文字評量，文字評量會覆蓋缺考 `Text`

**影響評估**：
- 根據舊版實務運作，此行為是系統設計的一部分
- 若業務需求不允許同時存在，需改用不同欄位（需確認後端結構）

**建議**：
- 測試案例 3 需特別驗證此情境
- 若發現問題，需與後端確認 Extension 結構是否可擴充

### 風險 2：單引號 escape 行為
**說明**：
- 文字評量中的單引號會被 escape 為兩個單引號
- 讀取時後端應會自動還原，但需確認

**影響評估**：
- 沿用舊版 escape 行為，理論上應無問題
- 測試案例 5 需驗證單引號正確顯示

### 風險 3：一般分數與文字評量同時存在
**說明**：
- 修正後，一般分數時若存在文字評量欄位，`Text` 不會被清空
- 此行為符合需求，但需確認所有情境下都正確

**影響評估**：
- 測試案例 1、6 需驗證此情境
