# Todo - 高中評量成績「文字評量」輸入/儲存/讀取調整（0105）

## 目標
參考 `gradebook_old.js` 的文字評量處理方式，修正 `gradebook.js` 在「文字評量」的儲存邏輯，達成：
1. 使用者可在畫面輸入「文字評量」並成功儲存（SetCourseExamScoreWithExtension）。
2. 重新載入/重新開啟後可正確讀取並回填「文字評量」（GetCourseExamScore → Extension.Extension.Text）。
3. 支援「清空文字評量」：輸入空白/刪除後仍能送出更新，後端資料確實清空。
4. 不破壞既有的缺考/特殊成績（UseText/Text/Score）邏輯與分數儲存行為。

## 影響範圍
- 主要修改：`gradebook.js`
- 參考對照：`gradebook_old.js`
- 不建議改動：後端合約（DSA service 名稱/欄位結構），除非你已確認後端需要同步調整。

## 現況摘要（問題點）
`gradebook.js` 儲存階段雖然會用 `hasText` 判斷是否需要建立 `Extension` 殼，但沒有把
`studentRec['Exam' + ExamID + '_文字評量']` 寫入 `data.Extension.Extension.Text`，甚至在一般分數路徑會清空 `Text`，導致「存完消失」。

`gradebook_old.js` 則會一律把 `_文字評量` 寫回 `Extension.Extension.Text`（並處理單引號 escape），因此可正常保存與讀取。

## Todo 2 - 補齊「文字評量」寫入 Extension.Text（核心修正）
在 `gradebook.js` 組 `data` 的地方，新增/調整下列邏輯，使其與 `gradebook_old.js` 的儲存行為一致：

### 2.1 取得文字評量輸入值
- 取值來源：
  - `var textEval = studentRec['Exam' + examRec.ExamID + '_文字評量'];`
- 正規化：
  - 若為 `null/undefined` → 視為「未提供」（但仍要支援清空，見 2.2）
  - 若為非字串 → `textEval = '' + textEval`

### 2.2 判斷是否需要 Extension 殼（必須支援清空）
將既有：
- `if (hasText) needExtensionShell = true;`
改為「欄位存在」判斷，而非 truthy：
- 建議判斷之一（擇一實作）：
  - `var hasTextField = studentRec.hasOwnProperty('Exam' + examRec.ExamID + '_文字評量');`
  - 或 `textEval !== undefined && textEval !== null`
- 規則：
  - **只要欄位存在就建立 Extension 殼**（包含空字串），才能支援清空更新。

### 2.3 寫入 Extension.Extension.Text（不要被一般分數分支清空）
- 若 `needExtensionShell == true`：
  - 確保 `data.Extension` / `data.Extension.Extension` 已初始化。
  - **寫入**：`data.Extension.Extension.Text = <文字評量值>`
- 字元處理（參考舊版）：
  - 若後端為 SQL/字串安全需求，舊版做了單引號 escape：`text.replace(/'/g, "''")`
  - 建議：沿用舊版 escape 行為，避免後端/DSA 字串解析出問題。

> 注意：
> - 你目前 `gradebook.js` 可能在一般分數路徑把 `Text` 清空（例如 `Text = ''`）。
> - 請調整為：**若文字評量欄位存在，則不要清空 Text**，以免覆蓋使用者輸入。

**完成條件**
- 在所有會送出的 payload 中，只要 UI 有該欄位（包含空字串），`Extension.Extension.Text` 一定會被送出（可為空字串用於清空）。

## Todo 3 - 保留既有特殊成績/缺考 extension 邏輯（相容性）
`gradebook.js` 目前可能使用 `buildScoreAndExtension(rawValue, examExtensionMap)` 產生：
- `Score`
- `UseText`
- `Text`（可能是缺考代碼或 report_value）

請調整規則如下，避免互相覆蓋：

1. **缺考/特殊成績相關的 `UseText/Text/Score` 邏輯照舊**（不要因為文字評量而破壞）。
2. 「文字評量」僅使用 `Extension.Extension.Text` 這個欄位時，需釐清是否與缺考 `Text` 共用同一欄位：
   - 若後端的 `Extension.Extension.Text` 同時承載「缺考文字」與「文字評量」：
     - 你需要改用不同欄位（例如 Extension 內自訂節點）才不會衝突；但舊版顯示是共用 `Text`，代表系統設計可能就是共用。
   - 若舊版實務運作正常（缺考照存、文字評量也能存），則代表：
     - 缺考的 `Text` 多半是搭配 `UseText=true` 的語意，
     - 文字評量只是獨立內容（即便同欄位，後端或前端讀取時有分流）。
3. 實作建議（最小改動）：
   - **先寫缺考 extension（UseText/Text/Score）**
   - **最後再寫文字評量 Text**（或反之）要看你們系統語意：
     - 若缺考 `Text` 重要且不得覆蓋：文字評量必須存到不同欄位（需確認後端結構）。
     - 若舊版把文字評量寫到同一個 `Text` 仍正常：沿用舊版即可。

**完成條件**
- 缺考/特殊成績依舊能正常儲存與讀取，且文字評量不會把缺考代碼弄丟（或反之）。
